# 0006. Built-in multi-user auth with Better Auth

- Status: Accepted
- Date: 2026-09-27

## Context

Allotr must support basic multi-user login without requiring an SSO proxy.
The common pattern among popular self-hosted apps is: built-in local accounts
with an onboarding wizard, API tokens for integrations, OIDC as an option,
and optionally a trusted reverse-proxy header mode. Hand-rolling password,
session and OIDC code in a finance app is a large security surface.

Chat identities must be bound to users without needing a public URL.

## Decision

Use Better Auth on the shared Kysely/SQLite database. v1 provides: an
onboarding wizard (first user is admin), local accounts, OIDC, and scoped API
tokens (`read`, `propose`, `write`). A trusted-header mode for existing
forward-auth proxies is available but off by default. Passkeys and LDAP are
deferred.

Chat identities link via a short-lived one-time code generated in the web UI
and sent to the bot.

## Consequences

- Works for users with and without an identity provider.
- Depends on Better Auth's release cadence and security record; it must be pinned and watched.
- Linking needs no public URL and works the same for every future gateway.
- Trusted-header mode must be documented with clear warnings about proxy bypass.
