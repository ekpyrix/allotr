# 0004. SQLite with Kysely, Postgres-ready

- Status: Accepted
- Date: 2026-09-27

## Context

Workload: a few writes per user per day, a handful of users per install.
Self-hosters value zero-ops storage and simple backups. Multi-user login is
required, so every row must be user-scoped. Postgres may be wanted later by
larger installs.

Options: SQLite only; Postgres only; both from v1. Query layer: Kysely,
Drizzle, Prisma, raw SQL.

## Decision

Ship SQLite (WAL mode, STRICT tables, foreign keys on) as the only v1
database. Access it through Kysely with forward-only plain `.sql`
migrations and types generated by kysely-codegen. Keep SQL portable (no
SQLite-only features in queries without a documented PG equivalent) so a
Postgres dialect can be added later behind the same code path.

## Consequences

- One file to back up; no extra container; ideal on a Raspberry Pi.
- One integration-test matrix in v1.
- Single-writer concurrency; fine for this workload.
- Adding Postgres later needs a second CI matrix leg and migration set, but no query rewrite.
- No row-level security; per-user isolation is enforced in the query layer and tested.
